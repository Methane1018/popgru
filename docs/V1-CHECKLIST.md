#### 一條要先定的規則

**按壓的那一瞬間，前後只能有一件事改變。**

核心笑點是「站著 → 瞬間變扁」。如果站姿會隨機變來變去，
那一下硬切就同時發生了兩件事（換姿勢＋被壓扁），笑點會糊掉。

所以：**被按壓的那個狀態只能有一種站姿**（維持現在的 `tall`），
新姿勢只用在**不是按壓的時刻**。

## 固定流程：新增一個「會存起來」的欄位

這是二十三條開發紀錄濃縮出來的。**每次加欄位都照這張走**，
v0.11 那一串災難全部是漏掉其中一兩步。

1. **`blankMe()` 給預設值** —— 少了這步，舊裝置的鏡像會缺鍵，
   `undefined` 流進去會讓 Firestore **拒絕整批寫入**（v0.10.1）
2. **決定它是哪一種**，然後照那一種的規則掛：
   | 種類 | 怎麼寫 | 怎麼讀 |
   |---|---|---|
   | 絕對值（只有這台裝置在寫） | 加進 `ABSOLUTE_FIELDS` | `srvAbsolutes` 要有對應 |
   | 只增不減的清單 | `queueUnion` 或整份 union | `planSnapshot` 用 `mergeOwned` |
   | 計數表 | 巢狀物件（**不能用點號路徑**，v0.11.4） | `mergeCounts` |
   | 加減的數字 | `queueInc` | 快照要加回 `inc('欄位')`（v0.10.9） |
3. **訪客模式也要存**（`saveGuest` / `applyGuest`）
4. **任何改動它的地方都要同時改本機** —— `flush()` 會拿本機值寫出去，
   只改伺服器的話幾秒後就被自己蓋掉（v0.11.3）
5. **加測試**。`plan.js` 是純的，所以測得到 —— 把 bug 種回去確認測試會紅
6. **跑 `node check.mjs`**，它會抓上面大部分的疏漏
7. 新檔案有 `?v=` 的話，**`bump.sh` 要加進去**（不然瀏覽器永遠拿舊版）

Firestore 規則不用改 —— `users/{uid}` 是 `allow write: if isMe(uid)`，
新欄位本來就寫得進去。（但如果新欄位會被**別人**寫，那就要加規則。）

## 每次出貨前

```bash
./test/run.sh     # 純邏輯測試
node check.mjs    # 靜態檢查
./bump.sh         # 同步版本號（會順便跑 check）
```

`bump.sh` 會在檢查沒過時擋下來。**不要繞過它。**
