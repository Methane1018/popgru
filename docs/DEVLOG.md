# 開發紀錄：踩過的坑

> 這裡只記**靜悄悄壞掉**的 bug —— 畫面看起來正常、資料卻一個字都沒寫進去的那種。
> 每一條在 `check.mjs` 都有對應的檢查，`./bump.sh` 會擋。

## 這個專案的 bug 有固定形狀

幾乎每個嚴重問題都長這樣：**前端照常運作、使用者看得到數字在動、但資料沒進資料庫。**
因為所有寫入都包在 `try/catch` 裡，失敗只是 `console.warn`，沒有人會發現。

所以現在：寫入失敗會 `console.error` 印出錯誤碼，連續三次會在畫面頂端顯示紅色橫幅。
**存不進去卻裝作沒事，比原本的 bug 更糟。**

---

## 1. `gName` 沒宣告 → 新用戶建不出格魯

`onSignedIn` 用了 `gName` 但從沒宣告。那行剛好在 `try` 裡，**ReferenceError 被 catch 吞掉，
整段 try 直接中止** —— 後面建立格魯的程式碼完全沒執行。

- 表面症狀：清空暱稱後顯示「無名氏」
- 真正後果：新朋友登入不會拿到格魯，不會出現在名單
- 教訓：`catch` 不可以吞掉程式錯誤。`ReferenceError` / `TypeError` 要 `console.error` 大聲叫

## 2. 待送匣讀寫格式不一致 → 補送永遠失效

`recoverOutbox` 讀新格式（`items` 物件），`outboxAdd` 卻還在寫舊格式（單一 `target`）。
兩邊對不起來，補送讀不到任何東西。

- 成因：多重字串替換的腳本中途 assert 失敗，**在寫檔之前中止**，把已經成功的替換一起丟掉
- 教訓：逐項寫檔並立即驗證，不要攢到最後才寫

## 3. `me.loaded` 從沒被設成 true → 計數欄位完全不寫

`flush()` 用 `if (me.loaded)` 決定要不要寫回連續天數等欄位，但沒有任何地方設過 `loaded = true`。
結果連續天數、凍結卡、雙倍魚、幫忙額度**整批停止寫入**。

- 成因：同 2，又一次
- 教訓：`check.mjs` 加了「flush 寫回的欄位必須等於快照讀入的欄位」

## 4. 誤把空的快取快照當成伺服器資料 ★ 最貴的一個

Firestore 的 `onSnapshot` **會先回一份本機快取的快照，再回伺服器那份**。
頁面剛載入時快取是空的，第一份是「一份不存在的空文件」。
程式把它當真 → 連續天數讀成 0 → `flush()` 又把 0 寫回伺服器 → 真資料被蓋掉。
**每次重整都發生一次。**

我為此連續猜錯四次，都在修下游症狀。真正定位是靠使用者貼出主控台。

- 教訓一：症狀模糊時，第一件事是**讓失敗變得可觀測**，不是讀程式碼推理
- 教訓二：守衛要精準。第一版擋掉「所有快取快照」，結果連正常資料都進不來（見 5）

## 5. 守衛過寬 → 寫入對象變成 `null`

修 4 的時候擋掉了所有快取快照，導致格魯快照永遠進不來，`state.viewing.uid` 一直是 `null`。
而 `flush()` 是 `if (n && target)`，**target 為 null 時整段跳過** ——
格魯和小圈子總數兩份資料完全沒寫，只有個人資料寫得出去。

- 正確做法：只擋「文件不存在 **且** 來自快取」。快取裡有資料的快照是安全的
- 安全網：在自己家時，寫入對象直接用 `state.me.uid`，不依賴 viewing 有沒有載好
- 舊資料修復：待送匣裡記成 `"null"` 的紀錄，補送時會算回自己身上

## 6. 登入時寫 `ownerName` → 暱稱每次重整被蓋掉

`onSignedIn` 寫 `ownerName: state.me.name` 到格魯，但那時個人資料快照還沒到，
`state.me.name` 還是 Google 名字 —— **暱稱根本還沒讀進來**。

- 修法：登入當下只寫頭像；`ownerName` 由 `syncOwnerName()` 在兩份資料都載入後才對齊

## 7. 刪函式刪過頭 → 「送人」整整壞了兩個版本

v0.8 重構商店時，我用「從 `function showHatPicker` 刪到下一個 `/* --- ` 註解」的方式移除舊函式，
結果把夾在中間的 `showGivePicker` 一起刪掉了（一次刪掉 136 行）。

按下「送人」只是靜靜地丟 `ReferenceError`，畫面毫無反應。兩個版本沒人發現，
因為我的測試從來沒有真的點過那顆按鈕。

- 教訓：**用行號範圍刪程式碼很危險**，要確認範圍內只有你想刪的東西
- 防線：`check.mjs` 現在會比對 `show*` / `panel*` / `draw*` 開頭的函式，
  被呼叫卻沒有定義就擋下來（已驗證這條檢查抓得到這個 bug）

## 8. 一個大約四成機率會紅的測試

`ok('魚 = 50', ...)` 偶爾失敗，重跑又好了，找不出原因。

原因是**寶物掉落是整包程式裡唯一用到亂數的地方**。壓 50 下大約有四成機率
隨機掉到一個帶「魚 +X%」的寶物，魚就會變成 51。

修法不是把斷言放寬，是**把亂數固定住**：測試開頭覆寫 `Math.random`，
預設回傳 1（永遠不掉），要測掉落時才調低。整包測試因此變成確定性的 ——
同一份程式碼永遠給同一個結果。

- 教訓：測試裡只要有一個不受控的隨機源，紅燈就會失去意義
- 附帶收穫：亂數固定之後，才寫得出「沒點技能就永遠掉不到傳說」這種端對端驗證

## 9. 點得下去、但什麼都不會發生的技能

技能樹的第四層（自動液壓機、魔法手）是純「權限」型的節點 ——
`grants:'autopress'` 只是一個字串，要有別的地方去問 `grants('autopress')` 才有意義。

如果忘記寫那段實作，節點照樣畫得出來、照樣點得下去、點數照樣扣掉，
**然後什麼都不會發生**。這跟「送人」按鈕壞掉兩個版本是同一類故障：
畫面上完全看不出來。

`check.mjs` 因此加了兩條互相對照的規則：

- 每個 `grants:'X'` 都必須有程式碼真的去問 `grants('X')`（否則是空的大招）
- 每個被問到的 `grants('X')` 都必須有技能給得出來（否則是永遠拿不到的權限）

兩條都實際驗證過抓得到：把 `grants('autopress')` 改掉，第一條立刻紅。

## 10. 新增一個鏡像欄位，把所有人的寫入卡死

v0.10.0 在 `MIRROR_FIELDS` 加了 `magicDay`。舊裝置的 localStorage 鏡像是 v0.9 寫的，
**沒有那個鍵**，於是第一次快照時：

    pickd[f] = useMirror ? mir[f] : srv[f];   // mir.magicDay === undefined

`undefined` 被塞進 `state.me`，接著 `flush()` 把它寫進批次 ——
**Firestore 收到 undefined 會拒絕整批寫入**，不是跳過那個欄位。

結果：連點擊都送不出去，連續九次寫入全部失敗。而畫面上一切正常，
只有主控台在噴。（幸好 v0.9 那次災難之後把寫入失敗改成 `console.error`，
不然這次又是無聲的。）

修的不是 `magicDay`，是那一行：抽成 `pickMirror()`，鏡像缺鍵就退回伺服器值。
這個坑跟欄位是什麼無關，**只要以後再加一個 MIRROR_FIELDS 欄位就會再踩一次**。

另外加了一道保險絲：`flush()` 寫出去之前把值為 `undefined` 的欄位刪掉並 `console.error`。
寧可少寫一個欄位，也不要因為一個欄位讓所有點擊都停擺。

三條 `check.mjs` 規則：鏡像欄位都要在 `blankMe()` 有預設值、都要出現在 `srv`、
`pickMirror` 要擋 undefined。已驗證第一條抓得到（把預設值刪掉就紅）。

- 教訓：**Firestore 的 undefined 是整批失敗，不是局部失敗**
- 教訓：新增一個「會被鏡像的欄位」是一個跨版本相容性問題，不是加一行

## 11. 學會的技能，過幾秒又變回「可以學」

`learnSkill()` 先改本機、再排進待送匣，最長 20 秒後才真的寫進 Firestore。
但快照處理是這樣寫的：

    skills: Array.isArray(d.skills) ? d.skills : [],

**直接照抄伺服器的值。** 中間任何一次快照回音（買個東西、改個名字都會觸發）
都會把還沒寫出去的那個技能抹掉 —— 於是節點又變回可以點。

`treasures` 一模一樣的寫法，只是掉寶比較少見所以沒人注意到。

這兩個欄位都是用 `arrayUnion` 寫出去的，也就是**只增不減**。
既然只增不減，快照要做的就是**取聯集**，不是替換：本機可能有還沒寫出去的，
伺服器可能有別的裝置加的，兩邊都要留。抽成 `mergeOwned()`。

（`ownedHats` 早就是這樣寫的，只是當時是為了相容舊資料，沒把它當成一條通則。）

`check.mjs` 因此加了一條會自己找欄位的規則：掃出所有
`queuePatch({ X: arrayUnion(...) })` 的 X，然後確認快照處理裡的 X 是走 `mergeOwned()`。
**以後再加任何一個 arrayUnion 欄位，忘了合併就會被擋下來。** 已驗證抓得到。

- 教訓：`increment` 的欄位要加上本機待送量，`arrayUnion` 的欄位要取聯集。
  兩者都不能照抄伺服器 —— 快照永遠比本機慢一拍

## 資料庫用量

每次 flush 寫三份文件（`users` / `grus` / `meta/global`），三份都掛 `onSnapshot` ——
**寫下去就回推一次快照，那就是一次讀取**。所以「多久寫一次」直接決定每小時燒多少額度。

一度設成停手 1.5 秒就寫，單人每小時就燒掉約 7,200 次讀取。現在是 6 秒 + 20 秒保底，約 1,800。

放慢寫入不會掉資料：真正保命的是 `popgru.outbox`（待送匣）和 `popgru.mirror`（本機鏡像），
都在 localStorage，關頁面／當掉／離線都還在。
