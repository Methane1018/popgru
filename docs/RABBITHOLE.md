# 兔子洞：劇情彩蛋

> 這份是**寫作與美術的規格**，不是劇情本身。
> 劇情內容寫在 `js/story.js`，立繪放在 `src/story/`。

> **世界觀寫在 [LORE.md](LORE.md)。** 這段故事的目的不只是一段內容，
> 而是讓玩家手上的格魯有來歷 —— 先想清楚世界，再寫劇本會順很多。

## 這東西是什麼

一個「深入、但隨時可以回來」的深彩蛋。點進去會觸發一段劇情，
可能有解謎、可能很長。走完之後拿到一個以劇情命名的神話級寶物。

已定案（見 V1-PLAN.md）：
- 兔子洞**不是彩蛋**，是新的一類 `story`。彩蛋要藏，兔子洞**看得見但進不去**
- 所以它可以大方地擺在畫面上，也可以正大光明標「神話」

---

## 寫作時要遵守的五條

這五條不是美學意見，是**畫面和資料真的做得到什麼**。
照著寫，你寫完就能直接跑；不照著寫，之後得回頭改。

### 1. 一句話 ≤ 60 個中文字

手機寬度大約 400px。一個對話框放得下三到四行、每行約 18 字。
超過就要捲動，而捲動會打斷閱讀節奏。

長段落就拆成連續好幾句 —— 一句一個「點一下繼續」，那反而是節奏。

### 2. 隨時可以離開，而且回得來

**每一個場景結束就存檔。** 使用者可能在任何一句話中間關掉分頁。
所以：
- 場景要短（三到十句話），不要寫一個十分鐘不能停的段落
- 不要有「走錯就重來」的設計。解謎可以卡住，但不能倒退

### 3. 不要有失敗

答錯謎題可以給提示、可以嘲笑他，但**不能把人踢出去、不能扣東西**。
這是彩蛋不是關卡。

### 4. 分支要克制

每加一個分支，要寫的字數就乘二。建議：
- **主線是直的**
- 選擇用來改**語氣和細節**，不改路線（選了什麼會被記住，之後被提起）
- 真正的分歧留給結局，最多兩到三種

### 5. 這是寫給那八個人看的

這個遊戲最好笑的地方一直是「那是某個朋友的娃娃」。
劇情裡可以有內部梗、可以指名道姓、可以引用群組裡發生過的事。
**對八個人來說，具體性就是深度。** 寫得像商業遊戲反而弱。

## 資料格式

寫在 `js/story.js`。三種積木就夠了：

```js
// 對白
{ who:'gru', face:'normal', text:'……' }

// 選擇（改語氣不改路線）
choices: [
  { text:'往下看看', to:'deep' },
  { text:'算了',     to:null },     // null = 離開劇情，回到遊戲
]

// 謎題
ask: {
  prompt: '要問什麼',
  answer: ['正確答案', '也接受的寫法'],
  wrong:  '答錯時說什麼（要好笑，不要責備）',
  hint:   '卡太久給的提示',
}
```

`who` 對應立繪檔名，`face` 對應表情。`who:null` 就是旁白（沒有立繪）。

## 立繪規格

放在 `src/story/`，檔名 `<角色>-<表情>.png`，例如 `gru-normal.png`。

| 項目 | 規格 | 為什麼 |
|---|---|---|
| 尺寸 | **900×1200**（3:4 直式） | 手機上顯示約 160px 寬，900 給到 2～3 倍解析度綽綽有餘 |
| 背景 | **透明** PNG | 要疊在對話框和背景上 |
| 構圖 | 上半身或全身，**臉在上方三分之一** | 對話框會蓋住下緣，臉不能被切到 |
| 邊界 | 四周留 5% 空白 | 避免縮放時貼邊 |

**表情先畫三種就好**：`normal` / `surprised` / `sad`。
劇本寫到需要別的再加 —— 先畫十種表情有九種用不到。

現有素材裡 `1000021256.png`（那張近距離 3/4 特寫）構圖最接近立繪，
可以當格魯本尊的基準。

## 存檔（實作時要注意）

劇情進度存成兩個欄位：

```
storySeen: ['scene1','scene2', …]   只增不減 → 走 mergeOwned
storyAt:   'scene7'                  絕對值   → 走 ABSOLUTE_FIELDS
```

這兩條規則已經在 `js/plan.js` 裡了，加欄位時照著掛就好，
不要另外發明一套（那正是 v0.11 那一串 bug 的來源）。

# v1.0 範圍：夥伴登場（2026-09-11）

**v1.0 的劇情只做到「主要夥伴登場」。** 後面的章節之後再說。

## 流程

```
① 畫面某處出現一道電子裂縫
② 敲一下 → 裂縫變大
③ 多敲幾下 → 夥伴從裡面跳出來
④ 自我介紹、導入（一段完整的對話）
⑤ 之後他坐在角落，點他會講一些無聊的小對話
```

## 兩種對話介面

這是最重要的設計決定：**開場跟閒聊是兩種完全不同的東西，不能用同一個介面。**

| | ④ 開場 | ⑤ 角落閒聊 |
|---|---|---|
| 性質 | 劇情，要專心看 | 陪伴，順便聽聽 |
| 介面 | 底部對話框＋立繪，畫面其他地方變暗 | 角落的小對話泡泡 |
| 推進 | 點一下換下一句 | 自己幾秒後消失 |
| **能不能繼續壓格魯** | 不行（但隨時可以按「之後再說」離開） | **可以，完全不擋** |
| 存檔 | 每一句都記住看到哪 | 不用存 |

**閒聊絕對不能擋住壓格魯。** 那是核心迴圈，已經定案的原則是「隨時可以回去壓格魯」。

## 裂縫什麼時候出現

一個跟世界觀對得上的做法：**它是被你壓出來的。**

劇情設定是「警方追蹤到你們對外發出的訊號」—— 而那個訊號就是你們在壓。
所以裂縫不要一上線就出現，而是**這一次連續壓到一定下數之後才裂開**。
玩家會覺得是自己把它壓出來的，而那剛好就是故事的真相。

## 跟既有規則的衝突檢查

| 既有規則 | 怎麼遵守 |
|---|---|
| 壓扁沒有中間幀 | 裂縫和夥伴是**另一個圖層**，不碰格魯本體的切換 |
| 主格魯只回應你的手指 | 裂縫有自己的點擊範圍，不能跟格魯重疊 |
| 隨時可以離開 | 開場要有「之後再說」，下次打開從同一句繼續 |
| 不能關掉任何機制 | 夥伴登場前後，遊戲玩法完全一樣 |
| 資料不要另外發明一套 | 進度用 `storySeen`（mergeOwned）＋ `storyAt`（ABSOLUTE_FIELDS）|

## 要準備的東西

- **劇本**：開場一段（第一層的內容）＋ 閒聊 20～30 句（第二層的內容）
- **立繪**：夥伴的 normal / surprised / sad，另外**一張坐在角落的小圖**
  （角落那張會很小，大概 80px 高，所以要簡單、剪影要清楚）
- **裂縫**：可以畫、也可以用程式畫（電子感的東西用 CSS 做反而好看）
